# 「裁图优先于重绘」方案落地性评估（#57 验收催办③）

评估时间：2026-11-02。背景：C2 回归 b 项「原题还原」连续多轮 FAIL——SVG 重绘成功率长期波动（1→2→0/13），
「图待补」成为常态。验收报告（#57）建议改为：**识别时 VLM 返回插图 bbox → 后端裁原卷图 → figure 走 img 分支**，
SVG 重绘降级为可选增强。参考：JudgePeach/math-question-bank 的单题 OCR Harness。

## 结论：可落地，估时 0.5~1 天，与验收估计一致；建议做

## 一、现有基础设施盘点（关键：三个环节已就绪，缺口只有两处）

| 环节 | 现状 | 缺口 |
|---|---|---|
| figure 数据模型 | `{"kind":"img","data":"/uploads/questions/x.png"}` 分支**已存在**（packages/shared/src/figure.ts:2、index.ts:239 FigureImg） | 无 |
| figure 渲染 | `figureHtml` 已支持 img 分支（shared/figure.ts:1721），前端 `QuestionFigure`/print.ts/PDF 导出均走它 | 无 |
| figure 校验 | `routes/questions.ts:39` 已接受 `/uploads/` 开头的 img figure | 无 |
| 题图上传目录 | `data/uploads/questions/` 已有（folder=questions） | 无 |
| 转录定位 | 转录**按页分批**（routes/analysis.ts:88 逐页调 `extractPaperQuestions`），每题的来源页天然已知 | 转录 prompt/schema 未要求输出 bbox |
| 裁图能力 | **未装 sharp**（apps/api 无该依赖） | 需安装 sharp（better-sqlite3 原生模块已在本机跑通，sharp 同为预编译原生模块，风险低） |

## 二、改造方案（按改动点）

1. **shared/转录 prompt + 类型**（~0.5h）：`PaperExtractItem` 新增 `figure_bbox?: [number,number,number,number]`
   （归一化 0~1，[left,top,right,bottom]，相对本页照片）；转录 prompt 增加一条规则：
   has_figure=true 时必须同时给出插图在**本页照片**中的 bbox，框不住/看不清时置 null（不编造）。
2. **analysis.ts 转录循环**（~0.5h）：逐页转录时把该页上传路径记到每个 item（`_page_path` 内部字段），
   这样每题的裁图源与 bbox 配对，跨页不串。
3. **裁图模块**（~1h，新文件 `apps/api/src/figureCrop.ts`）：
   - sharp 读原页文件 → bbox×宽高换算像素 → 外扩 3% 边距 → `extract()` 裁图 → PNG 存
     `data/uploads/questions/crop-<no>-<时间戳>.png`；
   - 合法性校验：bbox 数值域 (0,1)、裁出面积 ≥ 原图 1%、宽高 ≥ 80px，不合法返回 null（降级重绘/图待补）；
   - sharp 失败（安装异常/损坏文件）捕获返回 null，不阻塞批改（与重绘同级的安全网语义）。
4. **流水线编排**（~1h，routes/analysis.ts）：优先级改为
   **裁图 → （裁图失败才）模板重绘 → （重绘也失败）图待补**；
   裁图成功时 `figure_img` 传给落库层，`figure_status='原图裁切'`；可选做一次批量视觉核验
   （复用 selfCheckFigures 的单次调用模式：「该裁图是否为该题完整插图」，不过就降级图待补）。
5. **落库层**（~0.5h，routes/logs.ts `figureJsonOf` + 提取链）：`figureJsonOf` 增加 img 入参分支——
   有 `figure_img` 时输出 `{"kind":"img","data":path}`（优先于 figure_spec 的 SVG）；错题与 photo_bank 同步生效。
6. **回归**（~1h）：smoke 增加裁图用例（伪造带 bbox 的转录结果走隔离实例断言 figure=img）；
   C2 用真实 6 图跑一轮，重点看 b 项（预期原题还原 13/13 有图，重绘成功率不再影响 b 项）。

## 三、成本与风险

- **AI 成本**：bbox 随转录顺带输出，**零新增调用**；可选视觉核验 +1 次批量调用（约每卷 1 次，可控）。
- **主要风险：VLM bbox 精度**。qwen-vl-max 类模型的定位精度中等，可能框偏/框小。缓解：
  ① 外扩 3~5% 边距；② 裁图面积/长宽比合理性校验（题图通常不会是细长条或全页）；③ 可选视觉核验兜底；
  ④ 教师端错题/题库编辑页本就支持换图（Bank.tsx 已有 img figure 上传），AI 裁错的教师可一键替换。
- **次要风险**：sharp 安装（公司代理需 npm 走代理，此前依赖安装均成功；预编译包无需本地编译）。
- **不改变现有安全语义**：识别不清仍走「待确认」，bbox 缺失不编造，全链路失败仍落「图待补」。

## 四、收益

- b 项「原题还原」从依赖重绘运气（0~2/13）变为**只要转录看到图就有图**（预期 13/13）；
- 错题本/题库显示的是**原卷真实插图**，比任何重绘都忠实，同时消除「重绘自检降级」这条不稳定链路的阻塞面；
- SVG 模板重绘保留为增强（裁图失败时的第一备选），存量 462 道模板图不受影响。

## 五、建议排期

一次性落地（0.5~1 天）：步骤 1~6 连做，C2 回归 b 项转 PASS 后关闭。
如需拍板（与 P0-71 的 qwen-vl-max 加一路可并行开发，互不依赖），回复「做裁图优先」即可开工。
